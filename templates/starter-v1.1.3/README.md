# FactoryStarter

Generated by the Universal AI Factory from template `dotnet-angular-postgres-ddd` 1.1.3.

## Layers (Domain-Driven Design, mandatory)

| Project | Depends on | Holds |
| --- | --- | --- |
| `FactoryStarter.Domain` | nothing | Aggregates, entities, value objects, domain events and business rules |
| `FactoryStarter.Application` | Domain | Use cases and ports (interfaces) the domain needs from the outside |
| `FactoryStarter.Infrastructure` | Application, Domain | PostgreSQL persistence (EF Core) and other adapters |
| `FactoryStarter.Api` | Application, Infrastructure | HTTP endpoints and composition root |
| `web` | the Api over HTTP | Angular user interface |

`tests/FactoryStarter.Tests/ArchitectureTests.cs` fails the build when a layer takes a forbidden
dependency. Business rules belong in aggregates and value objects, not in endpoints or services.

## Commands

- `dotnet build` and `dotnet test` in the repository root.
- `npm ci`, `npm test -- --watch=false` and `npm run build` in `web/`.
- The API reads `ConnectionStrings:Database` (PostgreSQL). Never commit real credentials.
- The web app calls the API on the same origin under `/api/...` (`HttpClient` is provided). The release
  package serves the Angular build from the API's `wwwroot`; other paths fall back to `index.html`.
- A `DomainException` thrown anywhere answers 400 with `{"error": "<code>"}`; other errors answer 500 without details
  (`ErrorResponses`), so endpoints need no try/catch for business rules.
- API endpoints can be minimal APIs in `Program.cs` or `[ApiController]` classes in the Api project (both are mapped).
- `/health` is liveness; `/health/ready` also checks the database (503 when it is unreachable).
- `Database:InitializeSchema=true` creates the tables of the current model on startup when they do not exist
  yet, also next to other tables (staging). It never alters an existing schema: add versioned migrations before changing the model of
  a database that already has data.
