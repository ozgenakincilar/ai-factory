# Universal AI Factory product vision

Planning baseline: `e1bced7230d89352ddf6e69aeae4bee71fd106bf` (Milestone 5B.2).
The Multi-Cloud Deployment & BYOC requirements below are approved product direction,
not implemented capabilities or authorization to provision resources.

## Mission

Build a reusable, project-agnostic AI Software Factory that helps customers turn requirements
into reviewed software and deliver that software through controlled, verifiable processes.
The .NET 10 Factory must support multiple projects and application technology stacks while
preserving human approval, project authorization and traceable evidence.

StockFlow is the first planned end-to-end pilot, on Azure in M14. RiftMind AI remains a
separate intended product and the original reference application. Neither application's domain
is a dependency of the Factory.

## Multi-Cloud Deployment & BYOC

Customers must be able to deploy applications generated by Universal AI Factory to Azure,
AWS or Google Cloud through either of two ownership models:

| Hosting model | Product requirement |
| --- | --- |
| Bring Your Own Cloud (BYOC) | Deploy into customer-owned cloud accounts, subscriptions or projects using explicitly delegated, least-privilege access. |
| Factory-managed hosting | Deploy into Factory-managed cloud environments with explicit tenant isolation and operational responsibility. |

Both models must use the same approval and verification safeguards. Hosting ownership must
not bypass project authorization, immutable deployment-plan identity or deployment evidence.
Azure comes first, followed by AWS and Google Cloud. Both ownership models are required for
each supported provider; the roadmap is a delivery sequence, not a claim of availability today.

Customers must be able to identify the target tenant, project, environment, cloud and ownership
model before approving a deployment. Successful delivery must include deployment evidence,
health-check results, release history and documented rollback/recovery procedures.
Credentials, Terraform state and sensitive plan values must stay outside agent prompts and
public diagnostics.

## Delivery boundaries

Application deployment means operating a release in a selected cloud environment. Source-code
artifact delivery means handing over versioned source/build artifacts without implying that an
application has been deployed. Desktop application generation, packaging and delivery are a separate M16 capability;
delivering an installer does not provision cloud infrastructure or authorize execution.

Cloud support does not imply identical services, regions, feature sets or operational behavior.
Supported capabilities and limitations must be documented per provider. Zero-downtime deployment
is not guaranteed across providers; availability and recovery expectations must be verified for
the selected application and deployment strategy.

## Current capability versus future direction

At the baseline, the Factory provides Analyst/Architect generation and authenticated human
decisions on existing stored reviews. Milestone 5B.2 approval does not execute agents, submit
generated output automatically, apply infrastructure or deploy an application. There is no
implemented Deployment Engine, Terraform provider integration or managed hosting service.
